Voxtral Realtime is Mistral's streaming recognizer{{cite:mistral2026voxtral}}. Every part of it is causal, from the front end's level to the decoder, so it consumes audio as it arrives and writes text a fixed delay behind it, one decoder step per 80 ms.

Voxtral Realtime

Design change. Against Qwen3-ASR:

  • The front end measures against a fixed level, so chunking never changes a feature.
  • The stem's convolutions are left-padded; the encoder is a 32-layer, 1280-wide stack built like a modern decoder (RMSNorm, SwiGLU, RoPE), causal, over a 15 s sliding window.
  • The projector stacks four 20 ms frames into one 80 ms group and maps it through an MLP.
  • The bridge adds each group to one decoder position's token embedding.
  • Each decoder layer's feed-forward input is scaled by a function of the delay (delay conditioning).
  • The decoder is a 26-layer, 3072-wide Ministral-style model (GQA 32:8, an 8192-token window, a tied head), and its output vocabulary includes [STREAMING_PAD] ("nothing new yet") and [STREAMING_WORD] ("a word starts here").

Why. Real-time transcription needs bounded latency, which a model that reads whole windows cannot give. Making every socket causal means the model never waits; the delay gives it a fixed amount of look-ahead instead, set per request. Because text and audio share positions, the context grows at a constant rate and each word's position is its timestamp, to within 80 ms.
