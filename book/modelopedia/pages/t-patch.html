A transformer works on a set of vectors. To feed it an image, the image has to be cut into tokens, and whatever the model should know about where each token came from has to be added explicitly. This chapter covers three combinators that do that: the patch embedding, the prefix tokens, and the learnt position embedding.

Patch embedding

A patch embedding cuts the image into non-overlapping p×p patches, flattens each to a vector of p²C pixels, and maps it to width D with one shared linear map. That is exactly a conv with kernel p and stride p, which is how it is built{{cite:dosovitskiy2020}}.

The patch size is the main resolution knob. Halving it quadruples the token count, and global attention's cost grows with the square of that. The patch16, patch14 and patch8 in a name are this knob. Three small variations appear across the families:

  • No bias (CLIP's towers): the projection has no bias, because a norm follows it before the first block.
  • A norm on each token: Swin (LayerNorm) and AIMv2 (RMSNorm) normalize every patch token right after the projection.
  • A remainder: a ViT may take an image side that isn't a whole number of patches. The conv simply drops the pixels past the last whole patch, so so400m_patch14_384 (27 patches of 14 is 378) drops the last 6 pixel rows and columns. Swin refuses such a geometry, because its windows must tile the grid.

On a hybrid, the patch embedding cuts a conv net's feature map instead of the image, usually with p = 1.

Prefix tokens

Prefix tokens are learnt vectors placed in front of the patch tokens. They are the same for every image, so they carry no image content of their own. What they hold comes from attending to the patches.

  • Class token{{cite:dosovitskiy2020}}: borrowed from BERT. It acts as a learnt pooling query that takes part in every layer.
  • Distillation token{{cite:touvron2021deit}}: follows the class token. It is trained against a teacher's predictions and has its own classifier (DeiT).
  • Registers{{cite:darcet2024registers}}: k extra tokens that no head reads. They give the model scratch space for the global computation it would otherwise do in background patch tokens (registers).

Families that pool by mean or attention (SigLIP, AIMv2, the GAP ViTs) often drop the class token altogether.

The learnt position embedding

A learnt vector is added to each position: one per patch of the grid the model was trained at, plus, by default, one per prefix token. ViT found that 1-d learnt embeddings worked as well as 2-d or relative ones{{cite:dosovitskiy2020}}. Trained embeddings do recover the grid: nearby patches end up with similar embeddings.

Under no_embed_class, the embedding covers the patches alone, and the prefix tokens join after it is added. That leaves the prefix tokens free of any position, which is what DeiT III, FlexiViT, the register models and C-RADIO use. It also makes the embedding a pure function of the grid, so it is simpler to resample{{cite:beyer2023flexivit}}.

The embedding is fixed to one grid. A bunsen ViT runs at the image size its embedding was learnt for; timm's resampling for other sizes is not in the kit. Swin has no absolute embedding at all. Its positions enter each window's attention as a relative bias, which is one reason it changes resolution more easily.
