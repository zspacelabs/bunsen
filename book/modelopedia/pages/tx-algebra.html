The vision transformers are the second half of the lineage. They look like a break with the conv nets, but they are built from the same algebra. A residual stream is perturbed by a run of branches. Each branch is normalized, mixes information, and is added back. Only the mixers are new. bunsen builds every family in this half as one of two generic models: the vision encoder (ViT and its descendants) and the staged vision encoder (Swin). As in the conv half, each family kit is just a policy that fills their slots.

model = head ∘ pool ∘ final ∘ stack ∘ normpre ∘ tokens ∘ patch [∘ backbone]

The macro shape

A ViT cuts the image into p×p patches, embeds each one as a token, puts learnt prefix tokens in front, adds a learnt position embedding, and runs a stack of identical encoder blocks over the sequence{{cite:dosovitskiy2020}}. A pool then turns the sequence into one vector for the classifier.

That isotropy is the first structural difference from the conv nets. Swin brings the pyramid back by merging neighbouring tokens between stages, so its feature maps have the same strides (4 to 32) as a ResNet's and it can be used in a ResNet's place{{cite:liu2021swin}}:

From a residual unit to an encoder block

Put a pre-activation bottleneck next to a pre-norm transformer block and they line up. Both keep a clean identity stream and normalize the input to each branch. The bottleneck mixes channels (1×1), then space (3×3), then channels again, all inside one residual. The transformer block factors the two kinds of mixing into two residual sublayers: self-attention mixes tokens, and the MLP mixes channels within each token.

The board

The transformer chapters draw their variants on a second fixed board. The chassis on top gains the slots the conv board had no use for: a backbone (hybrids only), the patch embedding, the prefix tokens and position embedding, a norm before the stack, and a norm on either side of the pool. Below the chassis is one encoder block, drawn as its two residual sublayers. Each sublayer has the same five sockets. The norm sockets pre, post and out encode norm placement: a variant shows its norm placement by which of them it fills.

As before, solid chips are injected components and link to their combinator chapter. Dashed sockets are empty jumpers, and Δ marks what a variant changes relative to its parent. The shortcut socket of the conv board is gone, because in a transformer block it is always the identity.

Algebraic laws worth knowing

  • A pre-norm stack telescopes. xL = x0 + Σi fi(LN(xi)). This is ResNetV2's identity-mapping law{{cite:he2016id}}, and it is why pre-norm transformers train without the learning-rate warm-up post-norm ones need{{cite:xiong2020}}.
  • The patch embedding is a conv. Kernel = stride = p. Run on a conv net's feature map with p = 1, it is a 1×1 conv, and the result is a hybrid.
  • The MLP is two 1×1 convs. It acts on every token alone, so it commutes with any permutation of the tokens.
  • Attention can express convolution. Multi-head attention with relative position terms and enough heads can reproduce any convolution's receptive field{{cite:cordonnier2020}}. ViT drops the bias towards locality, and window attention puts it back as a hard constraint.
  • Patch merging is a 2×2 stride-2 conv. Space-to-depth (pixel-unshuffle) followed by a 1×1 projection{{cite:shi2016pixelshuffle}}.
  • A class token is a pool spread over depth. The class token is a learnt query that takes part in attention in every layer. The attention pool is the same idea applied once, at the end.

From a family's vocabulary to slots

This half pushes the conv half's lowering further. ViT, the CLIP towers, SigLIP, DINOv2, AIMv2, BEiT3, C-RADIO and the hybrids are all prefabs of one policy, bunsen's ViTContractConfig, which mirrors timm's VisionTransformer knobs{{cite:timm}}. DeiT's policy wraps it and adds distillation. Both lower to the vision encoder's structure. Swin's policies lower to the staged encoder, whose blocks are the same decoder-block combinator with window attention plugged into the token-mixer socket.

So a "family" on this side is a setting of knobs on one policy. Several of the chapters ahead are therefore grouped by lineage and training story, not by kit, and the circuits show exactly which sockets each one changes.
